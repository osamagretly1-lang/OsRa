OsRa R105 — نسخة كاملة نظيفة مع إصلاح استعادة الروابط
=================================================

ما الذي تغير؟
1) إصلاح عيب حفظ حالة الرابط: كان التحقق يغيّر نسخة مطبّعة مؤقتة من sourceLinks ثم يحفظ سجل الصورة القديم؛ لذلك قد يبقى رابط الملف المفقود معلّمًا بأنه صالح. R105 يحدّث سجل sourceLinks الأصلي ويحفظ حالة الفشل فعليًا، فيعود الرابط غير الصالح إلى مسار إعادة الربط. كما يعزل التحقق من الملف المباشر عن البصمات القديمة الموجودة في روابط المجلدات الأخرى.
2) رفض الإذن وحده لا يعتبر دليلًا على أن الملف مفقود؛ لا يتم إبطال الرابط لمجرد أن المتصفح لم يمنح إذن القراءة.
3) الملف الذي تختاره وتؤكده يدويًا يُتحقق لاحقًا ببصمته أو بياناته الخاصة، لا ببصمات روابط أخرى قديمة على سجل الصورة؛ هذا يمنع البصمة القديمة من إبطال ملف سبق أن أكدته بنفسك.
4) عند فشل المطابقة الآلية، لا يكتفي OsRa برسالة «لا توجد مطابقة»: تظهر لكل صورة ناقصة إمكانية اختيار ملف واحد ومقارنة الصورتين جنبًا إلى جنب، أو البحث البصري ومراجعة المرشحين. لا يُحفظ أي ربط يدوي إلا بعد تأكيد المستخدم.
5) لا يوجد ربط تلقائي بالاسم وحده، لتجنب ربط صورة خاطئة.
6) الاحتفاظ بتحسينات الربط متعددة المرشحين ومسار المصدر السريع، مع إصلاح مسار اختيار الملف الواحد الذي كان يُلغى في نهاية ملف الإصلاح.
7) تضمين تعديل R104 لصورة اليوم: تظهر الصورة في منتصف الإطار كاملة، من دون قص أو إزاحة برمجية.
8) تحديث Service Worker إلى build جديد يمسح كاش OsRa-v122 القديم ويعيد تحميل الصفحة عند اكتشافه، لتقليل استمرار ظهور JavaScript قديم بعد النشر.

ما الذي لم يتغير؟
- لم يتم حذف أو تعديل أي ملف داخل مجلد assets؛ كل ملفات الصور والرقصات والشخصيات والوضعيات محفوظة كما وردت في آخر ZIP رفعه المستخدم، وبصمات SHA-256 متطابقة.
- الصور الأصلية وبيانات OsRa المحلية ليست داخل هذا ZIP أصلًا؛ لا يحذف هذا التحديث قاعدة البيانات المحلية ولا يستبدلها. لا تمسح بيانات Chrome أو مساحة تخزين الموقع.
- تم الإبقاء على ملفات التشغيل الحالية، والأيقونات، وملفات manifest، وكل مجلدات الأصول الحالية.

طريقة التثبيت
1) احتفظ بنسخة من ملف ZIP الحالي ومن بيانات OsRa المحلية قبل أي تحديث.
2) فك ضغط هذا ZIP. ستجد index.html وapp.js وlink-fix.js وstyle.css وsw.js في الجذر مباشرة.
3) ارفع محتويات المجلد إلى جذر مستودع GitHub نفسه الذي يحتوي index.html، مع استبدال الملفات المتطابقة. ارفع مجلد assets كاملًا أيضًا كما هو.
4) لا ترفع ZIP داخل المستودع بدل فك ضغطه.
5) افتح الموقع من جديد بعد اكتمال نشر GitHub Pages. قد يحتاج تحديث المتصفح إلى إعادة تحميل الصفحة مرة أخرى إذا ظل يعرض نسخة قديمة.

تنظيف الملفات القديمة
هذا ZIP لا يحتوي تقارير/ملفات تعليمات/اختبارات الإصدارات القديمة أو نسخًا مكررة من الصور في جذر المشروع. ملف CLEANUP_R105_FILES_AR.txt يسرد الأسماء التي حُذفت من الحزمة. رفع ZIP إلى GitHub لا يحذف تلقائيًا الملفات القديمة الموجودة مسبقًا في المستودع؛ احذف الأسماء الواردة في القائمة يدويًا فقط عند رغبتك في تنظيف المستودع. لا تحذف أي صورة أو ملف تشغيل داخل assets. القائمة قد تتضمن ملفات README/ملاحظات نصية قديمة داخل بعض مجلدات الأصول فقط؛ هذه ليست صورًا ولا ملفات تشغيل.

حدود الاختبار
اجتازت ملفات JavaScript فحص الصياغة، واختبارات عقد R105 لتأكيد حفظ حالة الروابط الفاشلة وعدم إبطال الرابط بسبب رفض الإذن، وفحص مسارات الأصول وملفات Service Worker. لم يُشغّل الموقع داخل هاتف المستخدم، ولم تُفحص الصور الحقيقية أو handles الخاصة به؛ لذلك لا أستطيع الادعاء أن كل رابط في مكتبتك قد أُصلح قبل اختبار النسخة بعد رفعها.
